# Changelog

## UNRELEASED

- **Fix: a turn woken while the agent was idle lost all of its context** — a background-task notification arriving between turns wakes a run that pi serves from the *persisted* transcript rather than from the ephemeral system message it normally assembles. The persisted system messages carry only pi's own named sections, and an extension's appended text is not a section, so the prompt reached the bridge as its recorded key minus that tail — a strict prefix. `resolveOrDerive` already handled the mirror case (an incoming prompt that *wraps* a known key, which is what a wrapping extension produces) but not this one, so it threw and failed the turn over text pi itself chose to drop. Observed live as two identical 48,966-char misses against a 52,910-char key, both ~3ms after a `background-task-notification`; the sections summed to 48,952 plus seven `

` joins, which is the truncation exactly. A known key that starts with the incoming prompt now resolves to that capture — everything the bridge projects comes from the recorded `systemPromptOptions`, not from the tail, so it still applies in full. Shortest key wins when a whole nested family matches; two keys that diverge after the prompt stay ambiguous and still throw, since guessing which agent's context files to send is the silent loss this resolver exists to prevent.
- **Fix: bound the file list carried forward between compactions** — each compaction re-injected the previous compaction's `readFiles`/`modifiedFiles` into the next summary prompt, and each entry already records its own union of those lists, so the carry-forward unioned a union and could only grow: one session climbed 62 → 99 modified paths over 15 compactions with no ceiling. Capped at 64 paths per category, filled newest-first, and paths from the current turn are never evicted — those are the ones a summary can still act on.
- **Add: `"debug": true` in `claude-bridge.json`, a system-prompt trace, and one log directory** — debug logging could only be turned on with `CLAUDE_BRIDGE_DEBUG=1`, which has to be set before pi starts and so is no use to a user already inside the session that failed; the config setting turns it on for the next turn instead. Env var and config are OR-ed, and a `false` in config cannot silence an env var someone exported deliberately for one run. Debug also now writes `claude-bridge-prompts.jsonl`: one JSON record per system prompt the bridge records at agent start or is handed on a turn, with the section breakdown behind it, and the full text of both sides of any `prompt-capture: no capture for this N-char system prompt` failure. That error is only diagnosable from the bytes, and the case that prompted this appeared on a resumed session that no one could reproduce on demand. The prompts are tens of kilobytes each, so they go beside the main log rather than into it. All bridge logs moved from `~/.pi/agent/` into `~/.pi/agent/logs/`, so they can be handed over or deleted without picking them out of the directory holding the user’s settings and config; `CLAUDE_BRIDGE_DEBUG_PATH` still overrides, and the others still follow its directory. The `prompt-capture: no capture for this N-char system prompt` error now ends by naming the trace file and, when debug is off, the config path that turns it on.
- **Fix: pi 0.86.0 broke tools, the system prompt, and every summarization takeover** — 0.86.0 moved the tool declarations *and* the system prompt out of `Context` and into the transcript: `normalizeContext()` folds both into a leading system message before any provider is called, and the branded `TranscriptContext` that reaches us carries nothing but `messages`. Three call sites still read the dead fields. `resolveMcpTools` read `context.tools`, got `undefined`, and served Claude Code an empty MCP tool list — which does not fail loudly: the model announces the work it is about to do and ends the turn having called nothing, or prints a `<function_calls>` block as plain text and invents the result. The provider read `context.systemPrompt`, so `resolveOrDerive` was handed nothing and returned `undefined` instead of throwing, and Claude Code ran with none of the user's context files, skills, or `--system-prompt`/`--append-system-prompt` text — the exact silent loss that resolver's throw exists to prevent, reached by the one path it cannot see. Confirmed with a probe: a bridge model could not name a codeword its `AGENTS.md` stated outright. And `isolatedStreamFn` required a context of exactly one user message, which is now `[system, user]`, so compaction and branch summarization threw on arrival and the handlers turned that into a cancelled compaction. Tools now resolve through `getCurrentTools()` and the prompt through `getCurrentSystemPrompt()`, both looked up at call time so pi versions below 0.86 — which `peerDependencies` still admits, and where the old fields are still populated — keep working on the fallback; the isolated path ignores the leading system message when counting. `tests/int-smoke.sh` now asserts a real tool call end to end, via a token the model cannot produce without reading a file; every other check in that suite passes on a run where Claude is handed no tools.
- **Fix: `/bug` failed on a bridge model** — pi 0.86.0 added `generateBugReportSummary`, which `agent-session`'s `summarizeForBugReport` drives with `this.agent.streamFunction`, so on a bridge model it reaches the provider carrying pi's `BUG_SUMMARY_SYSTEM_PROMPT` — a prompt no `before_agent_start` recorded, which the resolver refuses by design. Compaction and branch summarization avoid this by taking over `session_before_compact` and `session_before_tree`; there is no `session_before_bug_report` to take over, so the provider recognises a pi-internal one-shot summarization by shape instead — one user message, no tools offered, a system prompt we never recorded — and routes it to the isolated path. Recognising the shape rather than the prompt text also covers the next internal consumer before we learn it exists. It was reachable from the bridge's own error text, which tells the user "/bug sends a report to the developers".
- **Bump: pi devDependencies to 0.86.0** — `@earendil-works/pi-ai`, `pi-coding-agent` and `pi-tui` were pinned at `^0.83.0`, so the suite tested against a pi that predated the transcript move and could not have caught any of the above. `peerDependencies` stays at `>=0.82.1`, which the call-time lookups support. The bump also surfaced the `/bug` consumer through `tests/unit-pi-streamfn-inventory.mjs`, which is what that inventory is for.
- **Tests: the unit suite overwrote the developer's own `~/.pi/agent/claude-bridge.json`** — `unit-config.mjs` redirected the global config by setting `HOME`, which `getAgentDir()` never reads: it resolves `PI_CODING_AGENT_DIR` and then a platform default, so on Windows every fixture landed in the real agent dir. One `npm run test:unit` was enough to leave the suite's malformed-config fixture (`{ "askClaude": { "enabled": true }, }`) sitting in a live install, breaking the next pi start. The harness now redirects `PI_CODING_AGENT_DIR`, which is the override `getAgentDir()` actually honors.
- **Fix: every new session failed with "No conversation found with session ID"** — pi opens a session with `[system, user]`, and `turnStart` walks back over the trailing user turn only, so the priors handed to the rebuild were `[system]`: non-empty, so the clean-start guard missed, and `convertPiMessages` emits no record for a `system` message. `cc-session-io` writes no file for a session with zero records, so the rebuild reported `file missing after save — ENOENT` and then returned the id anyway, which pi passed straight to `resume`. A rebuild that imports nothing is now treated as the clean start it is.
- **Fix: the model had no context at all after a compaction (issue #101)** — compaction at a tool boundary interrupts the parked Claude Code query, and an interrupted CC subprocess keeps writing: it flushes its own `[Request interrupted by user]` record into the session JSONL, parented on a uuid from the conversation pi just replaced. The rebuild that follows was an *in-place* one — `deleteSession` plus `createSession` on the same id — so that late record landed in the freshly written file naming a parent no record defines. Claude Code resumes by walking `parentUuid` back from the leaf, not by reading the file top to bottom, so it stopped at the dangling link and replayed only the records after it. Observed as a rebuilt 248-record session whose record `[0]` was the compaction summary, of which CC replayed 152 records starting at index 46: the summary and the entire kept tail reached the API as nothing, and the model opened the next turn with no context. The discard now rotates to a fresh session id and leaves the old file for the orphan to finish writing into, which is what `forceRotate` already did after an abort — the flag's doc comment asserted compaction could not produce a concurrent writer, which stopped being true when the parked-query discard was added. A session is also checked before it is resumed: a broken parent chain forces a rebuild instead, and `verifyWrittenSession` now reports one as an integrity failure. `tests/int-compact-continue.mjs` covers the whole path against a live compaction, asserting the resumed session's parent chain reaches its root — the model's own recall is not a reliable signal here, since it can name a codeword the summary carries even on a run where the summary never reached the API.
- **Fix: bump `@anthropic-ai/claude-agent-sdk` → `^0.3.267` so Fable 5.1 (and other post-`0.2.141` models) actually run.** The bundled Claude Code CLI advertises its version to the API, which gates newer models behind a minimum client version. `0.2.141` reports Claude Code `2.1.141`; the API rejects `claude-fable-5-1` on it with `400 ... version 2.1.251 or newer is required`. `0.3.267` bundles Claude Code `2.1.267`, clearing the gate. The new SDK's peer requirement also forces `@anthropic-ai/sdk` → `^0.124.0` (was `^0.73.0`); the only `src` use is a type import, and `tsc --noEmit` stays clean.
- **Fix: an extension that appends to the system prompt before claude-bridge failed the turn (issue #101)** — `before_agent_start` hands each extension whatever the previous ones made of the prompt, so the bridge was recording the wrapper's prompt rather than pi's. That cost twice: the wrapper's own text (pi-hermes-memory's memory block, for one) is not in the capture and so reached Claude Code as nothing at all, and pi's own unwrapped prompt — which it still runs turns on, as after auto-compaction — then matched no key and failed the turn with "no capture for this N-char system prompt". The capture is now keyed on pi's prompt, rebuilt from the `systemPromptOptions` the event reports, so a wrapped prompt resolves through the embed path that carries every surrounding byte through unchanged. The builder is taken from the *running* pi, located through `process.argv[1]`: pi's extension loader resolves `import.meta.resolve` from the extension's own directory, which for a checkout finds its own devDependency, and a pi of another version builds a prompt that reproduces nothing. A prompt an extension rebuilt rather than wrapped, or one no reachable builder reproduces, still keys on itself as before.
- **Fix: compacting mid-turn could loop, compacting again every turn (issue #101)** — a turn that ends on a tool call leaves the Claude Code query parked waiting for its result, and pi can compact at exactly that boundary. The tool-result path is the one provider call that never syncs the shared session, so the `needsRebuild` set by `session_compact` was never read: the result went into the parked query, CC answered over the pre-compact conversation and reported its full usage, and pi crossed the same threshold again on the next turn. Observed as eight compactions in eight minutes with `cacheRead` never dropping below 123K. A query whose conversation pi has rewritten is now discarded at that boundary, and the result carries the turn into a fresh query over the compacted history. Whether pi rewrote its history is tracked independently of which Claude Code session is known: `sharedSession` does not exist until a query *completes*, so tracking it there armed the discard everywhere except the first turn — and a first turn long enough to compact never completes, which is the shape the bug was reported in.
- **Tests: integration suite could not run on Windows** — the RPC harness split `PATH` on `:`, which shreds every Windows path at its drive letter, and spawned `pi` rather than npm's `.cmd` shim; it now splits on the platform delimiter and spawns `node` on pi's resolved entry point. Adds unit coverage for recording a history rewrite before any Claude Code session is known, the case `unit-discard-rewritten-query.mjs` tested the mechanics of but never the decision to enter.
- **Fix: git-status changes no longer bust the prompt cache (issue #73)** — the `claude_code` preset embeds a git-status snapshot in the cached system block, so any git transition (new file, staging, commit) rewrote the whole conversation prefix at cache-write rates. The provider path now sets `includeGitInstructions: false`, stripping the block with no other cost.
- **Fix: rate-limit warning showed 1% and repeated every request** — the SDK reports `utilization` as a fraction (0.98), but the notification rounded it directly, printing "1% used" at 98% of the window. It now shows true percentages and only re-notifies when usage rises past a new 5% step or the threshold changes, instead of once per request while over the threshold.
- **Fix: an exhausted Claude subscription never triggered fallback models (issue #58)** — Claude Code words a spent quota as "You're out of extra usage · resets 6:30pm", which names no recognizable symptom, so pi-subagents' `fallbackModels` and similar retry logic read it as a fatal error. A failure preceded by a rate-limit rejection is now labelled as one, with its limit type and reset time. Also fixes the rate-limit notification showing a 1970 reset time.
- **Fix: better isolate AskClaude tool (issue #59)** — AskClaude children no longer inherit the user's `~/.claude` `CLAUDE.md` files or skill listing, and now always get Claude Code's system prompt preset instead of only when pi-side skills exist. Thanks @JAtkinsonKO.
- **Fix: Bogus debug message about "record count mismatch" after switching providers** — the post-rebuild integrity check did not take `@file` expansion into account when switching providers.

## 0.7.0 — 2026-08-08

- **BREAKING: AskClaude tool now off by default** — If you want to continue using the AskClaude tool, set `askClaude.enabled` to `true` in your config (see README.md).
- **New: mid-turn steering actually works (issue #39)** — a steer sent while a tool was running used to be stashed and replayed as a follow-up after Claude's whole turn finished. The prompt is now a long-lived streaming generator and the steer is written to CC's stdin (`priority: "next"`) before the tool result is released, so CC drains it at that tool boundary and acts on it in the same turn.
- **Fix: system prompt loading** — Claude Code now receives the same global and hierarchical `AGENTS.md` / `CLAUDE.md` files that Pi loads. Config settings`provider.appendSystemPrompt` / `provider.settingSources` are no longer needed and have been removed gone). Improved compatibility with for children agent (i.e. subagents) and for other extensions that modify the system prompt. Unhandled system prompt configurations should fail loudly rather than silently discarding instructions.
- **Fix: branch summarization ran through the live provider** — rewinding or forking with "summarize" runs through the *agent's* stream function, so unlike `/compact` the request reached this provider and the live Claude Code session rather than an isolated subprocess. The bridge now takes over `session_before_tree` the way it already took over `session_before_compact`.
- **Fix: `@file` mentions were lost when a session was rebuilt** — Claude Code expands an at-mention itself (unlike pi) and stores the file's contents as an `attachment` record in its own session file; pi never sees it, so a rebuild kept the prompt text and silently dropped the file the model was reasoning about. Expansions are now carried across. Requires cc-session-io `^0.4.0`.
- **Fix: images dropped from prompts and rebuilt sessions (issue #34)** — an image followed by a trailing text preview lost the image, and tool results carrying images were flattened to text whenever the bridge rewrote pi's history into a Claude Code session. Images survive both paths now.
- **Fix: session rebuilds could corrupt turn structure** — pi records one message per tool result, and `repairToolPairing` (applied inside `Session.importMessages`, so unavoidable) only pairs results sharing the user message right after their assistant message, so tool results past the first can become `[no tool result recorded]`; a turn's results are now collected into one message placed directly after its assistant message. Minor: a turn aborted before anything streamed was rebuilt as `[incompatible content omitted]` potentially misleading the agent into thinking it is missing something. Empty turns are dropped now, while genuinely filtered content keeps its slot and label. Rebuilds also incorrectly wrote pi's bare model id instead of the resolved CLI id, dropping the `[1m]` suffix (issue #42; minor metadata fix only, since `--model` was already correct).
- **Fix: errored turns could report as a successful stop** — CC flags failures with `is_error` on a result whose subtype is still `"success"`, so the bridge duplicated the error text and finalized normally (issue #43); failed results now end the turn with `stopReason: "error"`, and the compact-summary path no longer accepts an errored result. Separately, a turn that ended on a tool call has its pi stream closed, and the guard suppressing content events for a closed stream also swallowed the `result` message, so a 429 or overload mid-tool set no `stopReason` and logged nothing (part of issue #35). The no-event stream watchdog idea in #35 has not been addressed.
- **Fix: a reentrant subagent could disturb the parent's session** — the shared session cursor was written from whichever context delivered tool results, so a background subagent dragged the parent's cursor backwards and cost its next turn a full rebuild and a flushed prompt cache. Removal from the active-context set is now guarded like the cleanups beside it, and an orphaned tool result no longer resets the live top-level context's turn state.
- **Fix: bridge could deadlock on a tool name Claude can't call** — Claude sometimes called `bash` instead of `mcp__custom-tools__bash`; CC rejected it with "No such tool available" and retried under a fresh tool_use id, but the bridge had already run the rejected call, so the retry's MCP handler waited on a result that never came. Calls for anything the bridge does not serve over MCP are now ignored. Rebuilt transcripts contributed to this by sometimes naming tools as `Bash`/`Read`/`Edit`/`Write` in past calls; those names now stay in the `mcp__custom-tools__` namespace.
- **Fix: nested tool schemas flattened (issue #44)** — converting pi schemas to Zod collapsed nested objects and dropped `anyOf`/`const`, so Claude saw only the top level of tools like `edit` and `subagent`. The MCP server now serves pi's JSON Schema verbatim.
- **Fix: tool results paired by call order** — MCP handlers took their `toolCallId` from a positional cursor, so a call arriving out of order silently paired its result with the wrong tool call. Now pairs by Claude's `_meta["claudecode/toolUseId"]` and fails loudly if it is absent.
- **Fix: Claude Code could write memory from bridge turns** — provider and AskClaude queries now disable auto-memory through the SDK; set `provider.autoMemoryEnabled` to `true` to opt in if you actually want it. Isolated compaction queries always disable it.
- **Tests: suites now drive the real code** — `tests/lib/record-sdk-streams.mjs` captures verbatim SDK streams (scrubbed, and refusing any fixture the username survived) for `tests/unit-stream-replay.mjs`, replacing hand-written messages that missed the `system/status` and `rate_limit_event` frames a real stream carries. `tests/int-shutdown-kills-cc.mjs` pins that a pi shutdown and a user abort each reap the Claude Code subprocess with a tool call in flight.
- **Tests: correctness audit tooling** — `diag/audit-{transcripts,cache,warnings}.mjs` scan session transcripts and the bridge log for silent data loss, prefix-cache breaks and stranded tool handlers, gated on `--since`; `diag/replay-write-path.mjs` replays any pi session through the rebuild. `tests/int-cc-contracts.mjs` pins the undocumented Claude Code behavior the bridge depends on against the installed SDK, and `tests/unit-convert-determinism.mjs` pins that a rebuild is deterministic and extends the previous transcript rather than rewriting it.
- **Internal: trim redundant dependencies** — pi bundles typebox and its extension loader always aliases the import to that copy, so shipping our own only made consumers install a redundant one that pi ignores. Now `peerDependencies: "*"` plus a devDependency for typechecking, as pi's packaging docs require; dev peers track pi 0.83.0. `@anthropic-ai/sdk` moves to devDependencies for the same reason — it is only ever imported for types.

## 0.4.0 — 2026-05-04

- **Fix: Opus 4.7 + xhigh sent wrong effort to SDK** — pi-ai 0.72 ships per-model `thinkingLevelMap` overrides (e.g. `claude-opus-4-7` declares `xhigh→xhigh`, not `xhigh→max`), but our hardcoded `REASONING_TO_EFFORT` table ignored them. Effort lookup now consults `model.thinkingLevelMap` first, falls back to the table for older pi-ai or unmapped levels. Forwarded `thinkingLevelMap` through `buildModels` projection.
- **Fix: zero out model cost in `buildModels`** — per-token pricing in the footer was wrong because models inherited pi-ai's non-zero cost fields, which pi then multiplied by the huge token counts from the SDK. Now explicitly zeroed so pi's footer shows no cost.
- **Use `tools: []` instead of `disallowedTools` blocklist** — switch from blocking specific tools to explicitly passing an empty tools list, preventing any new default tools from silently leaking into bridge sessions.
- **Disable CC-side autocompact (`DISABLE_AUTO_COMPACT=1`)** — pi already owns context management and propagates its own `/compact` to CC. Letting CC autocompact too double-flushed the prompt cache and raced pi's threshold; manual `/compact` in CC is unaffected.
- **Fix: pi `/compact` no longer triggers CC autocompact-thrashing (issue #8)** — pi's compaction shrinks its messages array, but `syncSharedSession`'s REUSE check (`slice(cursor)`) silently returned `[]`, so the bridge kept `--resume`ing the pre-compact CC session JSONL. Over long sessions CC's own autocompact then refilled within 3 turns and tripped its anti-thrashing guard. Now subscribes to pi's `session_compact` event and forces the next sync down the REBUILD path so CC sees the post-compact history. Also subscribes to `session_tree` (branch nav has the same shape).
- **Refactor: split `needsRebuild` into `needsRebuild` + `forceRotate`** — only the abort case needs UUID rotation (to dodge late writes from the dying CC subprocess). Compact/tree now rebuild in place, preserving the sessionId and not leaking orphan JSONL files into `~/.claude/projects/`.
- **Block user-installed MCP servers from leaking into bridge sessions** — pass `--strict-mcp-config` unconditionally and set `ENABLE_CLAUDEAI_MCP_SERVERS=0` in the spawned CC env, suppressing both filesystem (`~/.claude.json`, `.mcp.json`) and claude.ai cloud MCP servers. Override with `provider.strictMcpConfig: false`.
- **Consolidate config** — SDK plumbing (`appendSystemPrompt`, `settingSources`, `strictMcpConfig`) moved from `~/.pi/agent/settings.json` (`claudeAgentSdkProvider` block) to a `provider` block in `~/.pi/agent/claude-bridge.json`. Old location no longer read. Drop deprecated, unsafe `maxHistoryMessages`.
- **Bump deps** — `@anthropic-ai/claude-agent-sdk` → ^0.2.126; migrate to TypeBox 1.x (new import paths per pi-mono 0.69); pi devDeps → ^0.72.1. Extract `registerTool` schemas to const with explicit `<typeof params>` generic to avoid TS2589 deep-instantiation under TypeBox 1.x.
- **Internal: move sources into `src/`** — `index.ts` and the extracted modules now live under `src/`; screenshots under `assets/`. `pi.extensions` and published `files` updated accordingly.
